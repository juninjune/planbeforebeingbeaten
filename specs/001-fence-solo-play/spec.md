# Feature Specification: 울타리 치기 1인 플레이

**Feature Branch**: `001-fence-solo-play`
**Created**: 2026-11-21
**Status**: Draft
**Input**: 웹 퍼즐 게임 모음 서비스의 첫 게임. 로비에서 울타리 치기를 골라 한 판을 풀고, 정답이
완성되는 순간 완성 화면과 기록 시간이 나온다. 가입·설치 없음, 모바일 세로 화면 우선.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한 판을 끝까지 푼다 (Priority: P1)

사용자가 링크로 접속해 로비에서 울타리 치기를 고른다. 판이 열리면 변을 탭해 선을 긋고,
모든 숫자를 만족하는 하나의 닫힌 고리가 완성되는 순간 완성 화면과 기록 시간을 본다.

**Why this priority**: 이것이 게임 자체다. 이 흐름이 끝까지 되지 않으면 다른 모든 것은 의미가 없다.

**Independent Test**: 고정된 퍼즐 한 판만 있어도 검증된다. 로비에서 게임에 들어가 정답대로 변을
탭하면 완성 화면과 시간이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로비 화면, **When** 울타리 치기를 고른다, **Then** 숫자가 적힌 격자 판이 열리고 타이머가 시작된다.
2. **Given** 열린 판, **When** 빈 변을 탭한다, **Then** 그 변에 선이 그어진다.
3. **Given** 선이 그어진 변, **When** 다시 탭한다, **Then** X 표시로 바뀌고, 한 번 더 탭하면 빈 변으로 돌아간다.
4. **Given** 정답에서 변 하나만 남은 상태, **When** 마지막 변을 탭해 고리를 완성한다, **Then** 제출 동작 없이 곧바로 완성 화면이 뜨고 타이머가 멈춘 기록 시간이 표시된다.
5. **Given** 닫힌 고리지만 숫자가 맞지 않는 상태, **When** 더 아무것도 하지 않는다, **Then** 완성 처리되지 않는다.
6. **Given** 숫자는 일부 맞지만 고리가 닫히지 않은 상태, **When** 더 아무것도 하지 않는다, **Then** 완성 처리되지 않는다.
7. **Given** 완성 화면, **When** 새 판을 고른다, **Then** 같은 크기의 다른 판이 열리고 타이머가 처음부터 시작된다.
8. **Given** 완성 화면, **When** 로비로 가기를 고른다, **Then** 로비로 돌아간다.

---

### User Story 2 - 매번 새로운 판을 받고, 같은 판을 다시 열 수 있다 (Priority: P2)

사용자가 새 판을 시작할 때마다 서로 다른 퍼즐을 받는다. 모든 퍼즐은 답이 정확히 하나다.
판의 주소를 다시 열면 같은 퍼즐이 나온다.

**Why this priority**: 고정된 한 판만으로는 반복해서 플레이할 수 없다. 같은 판을 다시 여는 능력은
이후 여러 사람이 같은 판을 푸는 기능의 토대다.

**Independent Test**: 새 판을 여러 번 시작해 서로 다른 판이 나오는지, 판의 주소를 다시 열면 숫자
배치가 똑같은지 확인한다. 생성된 판마다 답이 하나뿐인지 자동 검증한다.

**Acceptance Scenarios**:

1. **Given** 판 화면, **When** 새 판을 시작한다, **Then** 이전과 다른 숫자 배치의 판이 열린다.
2. **Given** 어떤 판의 주소, **When** 그 주소를 새로 연다, **Then** 숫자 배치가 완전히 같은 판이 열린다.
3. **Given** 생성된 임의의 판, **When** 가능한 답을 모두 찾는다, **Then** 답은 정확히 하나다.

---

### User Story 3 - 판 크기를 고른다 (Priority: P3)

사용자가 5x5, 7x7, 10x10 중 판 크기를 고른다. 고르지 않으면 7x7이다.

**Why this priority**: 모바일에서 편한 크기를 기본으로 하되, 원작 크기(10x10)와 가벼운 크기(5x5)를 선택지로 준다.

**Independent Test**: 세 크기 각각으로 새 판을 시작해 끝까지 풀 수 있는지 모바일 화면 크기에서 확인한다.

**Acceptance Scenarios**:

1. **Given** 울타리 치기에 처음 들어온 상태, **When** 크기를 고르지 않는다, **Then** 7x7 판이 열린다.
2. **Given** 판 화면, **When** 5x5 또는 10x10을 고른다, **Then** 그 크기의 새 판이 열리고 타이머가 처음부터 시작된다.
3. **Given** 모바일 세로 화면의 10x10 판, **When** 판을 본다, **Then** 판 전체가 가로 스크롤 없이 화면에 들어오고 모든 변을 탭할 수 있다.

---

### User Story 4 - 실수를 고치고, 분위기 속에서 푼다 (Priority: P4)

사용자가 되돌리기와 전체 지우기로 실수를 고친다. 화면은 어둡고 긴장감 있는 두뇌 서바이벌
톤으로 연출된다.

**Why this priority**: 풀이 경험을 다듬는 요소다. 없어도 게임은 성립한다.

**Independent Test**: 선을 몇 개 그은 뒤 되돌리기와 전체 지우기가 기대대로 동작하는지 확인한다.
연출을 입힌 뒤에도 User Story 1부터 3까지의 자동 검증이 그대로 통과하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 변을 여러 번 탭한 상태, **When** 되돌리기를 누른다, **Then** 마지막 탭 한 번이 취소된다.
2. **Given** 선과 X 표시가 있는 판, **When** 전체 지우기를 누른다, **Then** 모든 변이 빈 상태가 되고 타이머는 계속 흐른다.
3. **Given** 아무 화면, **When** 화면 하단을 본다, **Then** 비공식 팬 프로젝트이며 원 방송 및 제작사와 무관하다는 고지가 보인다.

---

### Edge Cases

- 완성된 뒤에는 판을 더 바꿀 수 없다. 변을 탭해도 반응하지 않는다.
- X 표시는 메모일 뿐이다. X 표시가 어디에 있든 선만으로 정답 여부를 판정한다.
- 고리가 두 개 이상이면, 각 고리가 닫혀 있고 숫자가 모두 맞더라도 완성이 아니다.
- 선이 한 점에서 세 갈래 이상으로 만나거나 끝이 열려 있으면 완성이 아니다.
- 되돌릴 기록이 없을 때 되돌리기를 눌러도 아무 일도 일어나지 않는다.
- 주소에 잘못된 판 크기나 해석할 수 없는 판 식별값이 있으면 기본 크기의 새 판을 연다.
- 화면을 새로 고치면 같은 판이 빈 상태로 다시 열리고 타이머는 처음부터 시작된다.
- 화면을 가로로 돌리거나 넓은 화면에서 열어도 판 전체가 보이고 조작할 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 가입과 설치 없이 링크만으로 로비 화면을 보여줘야 한다.
- **FR-002**: 로비는 플레이할 수 있는 게임 목록을 보여주고, 사용자는 그중 하나를 골라 들어갈 수 있어야 한다. 이번 범위에서 목록에는 울타리 치기 하나만 있다.
- **FR-003**: 시스템은 새 게임을 추가할 때 기존 게임을 고치지 않고 목록에 등록할 수 있는 구조여야 한다.
- **FR-004**: 판은 점 격자와 칸으로 이루어지고, 일부 칸에는 0부터 3까지의 숫자가 표시돼야 한다.
- **FR-005**: 사용자는 변을 탭해 빈 변 → 선 → X 표시 → 빈 변 순서로 상태를 바꿀 수 있어야 한다.
- **FR-006**: 시스템은 그어진 선이 (a) 갈라지거나 교차하지 않는 하나의 닫힌 고리이고 (b) 숫자가 있는 모든 칸에서 그 칸의 네 변 중 선의 개수가 숫자와 같을 때에만 완성으로 판정해야 한다.
- **FR-007**: 시스템은 완성 조건이 충족되는 순간 별도의 제출 동작 없이 완성 화면을 보여줘야 한다.
- **FR-008**: 시스템은 판이 열릴 때 타이머를 시작하고, 완성 순간에 멈추고, 완성 화면에 기록 시간을 보여줘야 한다.
- **FR-009**: 제한 시간과 오답 패널티는 없어야 한다.
- **FR-010**: 완성 화면에서 사용자는 같은 크기의 새 판을 시작하거나 로비로 돌아갈 수 있어야 한다.
- **FR-011**: 시스템이 내는 모든 판은 답이 정확히 하나여야 한다.
- **FR-012**: 같은 판 식별값과 같은 크기는 언제나 같은 판을 만들어야 한다.
- **FR-013**: 판 식별값과 크기는 주소에 담겨, 그 주소를 열면 같은 판이 열려야 한다.
- **FR-014**: 사용자는 5x5, 7x7, 10x10 중 판 크기를 고를 수 있어야 하고, 기본값은 7x7이다.
- **FR-015**: 세 크기 모두 모바일 세로 화면(390x844)에서 판 전체가 가로 스크롤 없이 보이고, 모든 변을 손가락으로 탭할 수 있어야 한다.
- **FR-016**: 사용자는 마지막 탭을 한 번씩 되돌릴 수 있고, 판 전체를 빈 상태로 지울 수 있어야 한다.
- **FR-017**: 완성된 판은 더 이상 수정할 수 없어야 한다.
- **FR-018**: 모든 화면에 비공식 팬 프로젝트이며 원 방송 및 제작사와 무관하다는 고지가 보여야 한다.
- **FR-019**: 서비스의 화면, 문구, 그래픽에는 원 방송의 프로그램명, 로고, 출연자, 영상, 음악과 타사 상표명을 쓰지 않아야 한다.
- **FR-020**: 개발 환경에서는 자동화된 브라우저 테스트가 현재 판의 정답을 조회할 수 있어야 하고, 사용자에게 공개되는 판에서는 이 수단이 노출되지 않아야 한다.
- **FR-021**: 화면은 어둡고 긴장감 있는 두뇌 서바이벌 톤으로 연출하되, 자체 제작한 그래픽만 사용해야 한다.

### Key Entities

- **게임**: 로비 목록에 올라가는 단위. 표시명, 설명, 진입 화면을 가진다.
- **퍼즐**: 판 크기, 칸마다의 숫자(또는 비어 있음), 판 식별값으로 이루어진다. 답이 정확히 하나다.
- **풀이 상태**: 변마다의 상태(빈 변, 선, X 표시)와 되돌리기 기록.
- **플레이 기록**: 판을 연 시점부터 완성까지 걸린 시간. 이번 범위에서는 완성 화면에 보여주기만 하고 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 명령 한 번으로 서비스를 띄운 뒤, 로비에서 울타리 치기에 들어가 판이 열리기까지 탭 두 번 이내다.
- **SC-002**: 모바일 화면 크기(390x844)에서 5x5, 7x7, 10x10 각각에 대해 "새 판 시작 → 정답 고리 완성 → 완성 화면과 기록 시간 표시"가 실제 브라우저 자동 테스트로 통과한다.
- **SC-003**: 같은 자동 테스트에서 고리 미완성 상태와 숫자 불일치 상태로는 완성 처리가 되지 않는 것이 확인된다.
- **SC-004**: 세 크기 각각에서 생성한 판 100개가 모두 답이 정확히 하나임이 자동 검증된다.
- **SC-005**: 같은 판 식별값과 크기로 두 번 만든 판이 100% 일치한다.
- **SC-006**: 새 판은 어떤 크기든 사용자가 기다림을 느끼지 않는 시간(2초 이내) 안에 열린다.
- **SC-007**: 각 판 크기의 시작 화면과 완성 화면 스크린샷이 증거로 남는다.

## Assumptions

- 진행 순서는 (1) 고정된 한 판으로 끝까지 풀리는 최소 버전, (2) 판 생성과 유일해 보장, (3) 판 크기 선택, (4) 연출이다. 각 단계가 끝날 때마다 브라우저 자동 테스트가 통과 상태를 유지한다.
- 진행 중인 풀이는 저장하지 않는다. 새로 고침하면 같은 판이 빈 상태로 다시 열린다.
- 기록 시간은 저장하거나 비교하지 않는다.
- 조작은 탭(또는 클릭)만 지원한다. 끌어서 긋기는 범위 밖이다.
- 소리는 이번 범위에 넣지 않는다.
- 판의 난이도는 조절하지 않는다. 답이 하나이기만 하면 된다.
- 범위 밖: 멀티플레이, 다른 게임, 계정, 랭킹, 배포, 힌트.
- 서비스 표시명은 아직 정해지지 않아 임시 이름을 쓴다.
